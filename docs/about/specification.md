# Specification

The formal Software Requirements Specification for this project lives (or
will live) in `SPECIFICATION.md` at the root of the repository.

!!! note "Not yet written"
    `SPECIFICATION.md` is not present in the repo at the time of writing.
    Until it lands, treat the [Configuration](../configuration/index.md)
    pages and the [Analyst locked-down session](../scenarios/analyst-locked-down.md)
    scenario as the effective specification for the container's behaviour.

When the file is added it will cover, at minimum:

- User stories and business rules.
- Functional and non-functional requirements.
- The container's boot architecture (see
  [Architecture](../developer-guide/architecture.md)).
- Testing, verification, and documentation requirements.

The intent is that the specification is complete enough to rebuild the
project in another language and arrive at a homologous outcome.
